# A 93-edge partner for the existing parent

Fix the saved 98-edge path in one eight-dimensional face. For either endpoint t, allow the other face to use t and the 157 vertices outside the parent. Two opposite-face vertices are adjacent precisely if their eight-bit addresses agree. Thus a 93-edge partner starting at t and avoiding every other parent vertex gives a 192-edge nine-cube path. The candidate uses 94 vertices, 47 of each parity. [Main branch's construction review](https://github.com/hironaka-iori/Snake-in-the-box-in-9/blob/8931c1efdf9397211b2047b7fea8e446c5d642d3/milestones/217-long-parent-search/logs/compatible-parent-review.md).

### Which existing 93-edge arcs are closest?

Take every 93-edge window of every one of the 131 published 191-edge bank snakes. A window belongs to some eight-dimensional face exactly when its transitions use at most eight coordinates. Considering both endpoint orientations gives 828 qualifying indexed windows. Renaming the flip directions in order of first appearance gives 66 rooted classes. All relative rooted placements of a class in the partner face are obtained by the 8! coordinate permutations, translating the first point to t.

Counting forbidden parent vertices gives a minimum of **10 at t=0** and **12 at t=78**, across 5,322,240 placements. The respective minimizing representatives are entry 127, start position 0, reversed, and entry 4, start position 2, reversed. Thus every such placed arc would require at least that many of its vertices to be replaced to fit the selected endpoint. This is a lower bound for the specified collection of arcs. It establishes a concrete reason to seek a new shape directly in the complement. [Window extraction and independent verification](partner_orbits.py), [placement enumerator](partner_orbits.cpp), [per-class results](partner-orbits.json).

### The complete fixed-parent 93-edge question is now settled

**Theorem.** At neither endpoint, 0 nor 78, does the saved 98-edge parent have a compatible 93-edge partner. This allows every partner shape and any choice of its far endpoint. Any longer partner would have a 93-edge prefix starting at the same endpoint. Therefore this particular 98-edge path cannot yield a 192-edge nine-cube snake by a single crossing.

For a 94-vertex partner, select 47 vertices of each parity from the literal 158-vertex complement graph. Force the root selected and choose one far endpoint of the opposite parity. At each selected vertex count **all** its selected cube neighbours. The root and far endpoint must have exactly one such neighbour; each other selected vertex must have exactly two. Every induced path satisfies these clauses. For every saved square or induced six-cycle prohibit selecting all its vertices. The graph on selected vertices of an induced path is a path and cannot contain any cycle as a subgraph. These deductions contain every valid partner. The two resulting Boolean formulas are already contradictory without any dynamically added subtour clause. In particular, the exclusion does not depend on accepting a disconnected degree assignment as a path.

Both formulas were independently refuted by drat-trim using exported, compacted proof files. The root-0 core used 2,773,314 resolution steps; the root-78 core used 3,535,377. The compressed formula and core separately reproduce their recorded SHA-256 hashes. The input is the immutable parent JSON at round 217. Its git blob content has LF line endings; conversion to the recorded CRLF convention reproduces the project's published file hash. A separate positive control reconstructs an 82-vertex rooted partner at 0 and an 81-vertex partner at 78, joins the faces and checks all pairs. [Root-0 certificate receipt](partner93-0-totalizer-cadical195-checked.json), [root-78 certificate receipt](partner93-78-totalizer-cadical195-checked.json), [root-0 positive control](partner93-0-totalizer-cadical195-vertices82.json), [root-78 positive control](partner93-78-totalizer-cadical195-vertices81.json).

Run `python partner93.py 0 --checker /path/to/drat-trim` or substitute 78. The archives `partner-proof-ROOT.cnf.gz` and `partner-proof-ROOT.core.gz` can also be decompressed and checked directly, independently of the search. The 191-edge lower bound in dimension nine remains unchanged.

### Why the round-218 linear relaxation cannot prove this result

The proposed linear relaxation admits an explicit rational point of total weight **100** for each root, whereas the desired path needs 94 vertices. The assignments have denominator eight. For each nonroot v they satisfy the inequalities 2x−e ≤ s ≤ d−(d−2)x−e, where d is ambient degree and s is the sum of the selected fractions on its neighbours. They also satisfy all variable bounds, the free endpoint sum, parity equality, the root degree constraint and all 279 or 274 verified square/six-cycle inequalities. Therefore the maximum of this relaxation is at least 100 at each root. An upper-bound certificate below 94 for this relaxation is mathematically impossible. It is unnecessary to solve the linear program to optimality to establish that conclusion.
