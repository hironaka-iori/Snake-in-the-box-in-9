# Exact-CNF Lean replay: preparation and verified small controls

The checker source is derived from the uploaded project, rather than replaced by an unproved external oracle. LocalWindowModel imports Std only. LratCheckO5k supplies its tree-clause semantics and the general soundness theorems. The generated PeerLratFast5000W18 and cached PeerLratFast2_5000W18 variants preserve those proofs with three explicit encoding parameters: literal offset 5000, 18-bit proof words and literal parser fuel 2048.

These are necessary adaptations: the actual CNF has variable 4007 (too large for offset2400/4000), 116350 original clauses (too many for the cached17-bit format's 65536 flag boundary), and a learned clause of length1548 (longer than the original255 literal parser fuel). The maximum hint chain is3240, within the unchanged4095 hint fuel. These limits are checked before generation.

## Actual checked scope versus prepared scope

The small standalone checker/smoke source was genuinely accepted by official Lean4.19.0 through the official live.lean-lang.org service. The independent transcript audit found no errors or sorryAx. Its tiny UNSAT theorem has only the standard reported axioms propext, Classical.choice and Quot.sound. Additional small positive and negative controls exercise variable4007, clauseID70000, a300-literal LEARNED clause, rejection of missing hints, and rejection of a false refutation of a satisfiable CNF. The deliberately invalid control is expected to fail and must never be counted as a proved theorem.

The complete 7621-step/1604124-hint certificate has NOT been replayed by Lean. Its generated proof modules remain explicitly UNREPLAYED even though their formats and proof scripts use the small checked checker. Windows application-control policy blocks executing the downloaded native Lean on the present machine; no bypass was attempted. The public interactive server was not used for the giant replay.

## Full-CNF generation

Run generate_full_replay.py in the same directory structure. It retains every one of the116350 original clauses in the original order, with exact DIMACS-to-Lean literal decoding. It retains all7621 learned clauses and1604124 hints, rather than silently switching to a dependency core. It reuses the project's slot lifetime planner, segmentation, checkpoint semantics and final soundness composition. Packed data are kept in separate modules to permit bounded incremental builds.

The generator first independently checks the original RUP proof. It then simulates the exact packed Lean-format proof, including slot reuse, flagged start-database lookups and every checkpoint. Python-format success is not described as kernel compilation. The resulting theorem, if the generated modules compile, is exactly Unsat of the propositional CNF. It does NOT prove that the score gates, all cycle cuts or the geometric snake-to-CNF bridge have been formalized in Lean.

full_replay_manifest.json records the original CNF digest, project-generator digest, dimensions/fuel limits, segment statistics, generated byte counts and a topological build order. lrat_preparation.json records the hashes of the unmodified source checker dependencies. The only generator layout change keeps packed data in multiple modules; it does not change the proof computation.

## Ordinary native compilation on a supported Lean host

Use a legitimate working Lean4.19.0 environment. build_replay.py takes an explicit compiler path and performs ordinary sequential compilation, with per-module logs, source/olean hashes, exact imported-olean hashes, compiler executable hash/version and a resumable progress file. --plan never invokes the compiler and can use a stored toolchain identity. It downloads nothing and changes no application-control settings.

First inspect the compiler-free plan, then compile one module and inspect its output:

    python build_replay.py --plan --reuse --max-modules 1

    python build_replay.py --lean /path/to/lean --max-modules 1

Then continue in the same working installation:

    python build_replay.py --lean /path/to/lean --reuse

If the executable cannot run, the driver records TOOLCHAIN_UNAVAILABLE and stops. A successful .olean build is required before describing that module as checked. The main theorem is Snake9.LocalWindow.PointwiseScore22.unsat. PeerLratFinalAudit is generated reproducibly at the end of the build order and prints axioms for that exact final theorem. The driver rejects errors, sorry and nonstandard axioms, and only records ALL_COMPILED_AUDIT_PASSED after this final audit succeeds.
