# Exterior cube blocks around 191-edge catalogue placements

The five reconstructed 194-vertex hosts contain the catalogue pairs (44,473), (45,473), (465,473), (473,473) and (577,473), with catalogue rows numbered from one. Each reconstruction fits both complete parent paths independently to the relevant subsequences of a reference 191-edge word. Their equivalences to raw host rows 0, 2, 4, 6 and 7 are checked in host_isometries.log. The nine raw 194-vertex hosts in q8_all_191_positive.hosts are also used directly. Their 24 labelled witnesses from all pairs of host omissions cover ten different 191-edge classes; twelve of the witnesses cross between layers twice.

A candidate domain is the complete original host together with all exterior vertices in the chosen added blocks. Every host vertex is optional. Any number of changes to the order, use of either layer and any subset of available exterior points are permitted. The target is an open induced path of 192 edges or longer. For this optional-only domain a longer target witness can always be truncated to exactly 192 edges. These tests do not concern vertices outside their indicated domains.

The first two families open each coordinate 3-face and 4-face, retaining domains with at least four exterior points and deduplicating within placement. The next samples 2–4 scattered two- or three-dimensional faces. The last family opens independent horizontal squares in both layers, first at both projected crossing columns, then at one crossing column and a terminal column of a real 191-edge witness. All 28×28 horizontal direction pairs are used at the crossing-column pair; the endpoint pairs use a systematic one-in-seven sample of the second direction index.

The deletion solver bounds how many vertices can be omitted, enforces maximum degree two, and propagates articulation vertices that every sufficiently large connected selection must contain. The independent vertex-selection SAT encodings enforce degree, endpoint count and connectivity. One uses MiniCard with at-least cardinality and disconnected-component cut clauses. The CaDiCaL replay uses exactly 193 vertices with separate majority-color cases. It adds necessary reachability constraints along degree-two chains. The verification log reconstructs every raw-host four-face and confirms that a direct UNSAT or a tested UNSAT superset covers it. The five placement-specific geometries can be transported between isometric cubes by the supplied coordinate mappings.

To run from the workspace root, compile blocks.cpp with clang++ -std=c++20 -O3 and output it to /tmp/q9_fivehost_blocks_20261121. Run prepare.py, ten_paths.py and positive.py. The main solver arguments are mode, target edge count, per-domain limit and sample count. The direct runs used (1,192,4000,0) for 3-faces, (2,192,450,0) for 4-faces, and (3,192,500,450) for scattered faces on the raw hosts. The 3- and 4-face runs also used the reconstructed seeds.in. The SAT scripts require the local Python environment with python-sat. cover_sat.py produces cover_sat.log, then cd_retry.py takes that log to produce cover_retry.log. crossing_blocks.py writes the input cases; pool_sat.py takes the raw host file, case file and CASE for its first pass; cd_retry.py replays limits. The scattered-face run uses pool_sat.py on nine_multi.log with LIMIT+AUDIT, then tight_sat.py with LIMIT, then cd_retry.py. Reproduce the positive SAT controls with argument control to pool_sat.py, tight_sat.py and cd_retry.py. six_probe.py tests a further sample of larger domains. Output logs and .py/.cpp sources are retained. Run verify.py to check the final counts, geometric scope and witnesses. The negative answers are solver and enumeration results without saved proof traces.


The six_final.py replay increases the conflict cap for every initially limited enlarged 6-face probe. The final verification line records their resolved count, remaining limits and exterior-pool size range. These 108 sampled 6-faces are separate from the exhaustive 3- and 4-face families.
