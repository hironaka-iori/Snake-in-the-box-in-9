# 七分量以上的高维截面向九维拼接

输入是 5,002 条高维蛇的九维截面记录。其中 3,977 个截面含 7–18 个线性分量。每条记录中的编号为九维顶点。核验程序按九维图逐点重算所有诱导邻边。216 点的记录是以零为起点的第 98 行，它有 17 个分量。

试验从一个分量出发，在所选路径两端尝试短桥，翻转、截断和重排分量。也可把某个分量的一段异或平移到桥端，再沿原来的轴次序延伸。这允许放弃原来的分量或多次使用同一片段的不同平移。每次落点须在当前路径中恰有一个邻点。程序记录增长过程得到的最高长度和完整顶点序列。

| 独立批次 | 路径尝试数 | 片段放置尝试数 | 最长经检验边数 |
|---|---:|---:|---:|
| 全部 3,977 个合格截面 | 7,954 | 4,476,967 | 169 |
| 加强的 140 个截面 | 63,000 | 127,854,220 | 172 |
| 已知 191 边路径删去七个内部顶点，构成八分量阳性 | 6 | 2,400 | 191 |

每条输出均通过独立的全顶点对汉明距离检查。阳性输入不提供缺失的顶点，也不强制拼接次序。阳性关闭随机平移，只在原位置拼接，检验重连与验证逻辑。搜索结果不限制一般九维蛇的长度。

另有一个可逐截面复核的必要条件。若要保留输入森林的每一个点，连接某个分量的第一步必须从其端点走向森林以外的一个新点。这个新点至多有两个森林邻点，且其所有森林邻点均为分量端点。逐点检验发现，3,948 个截面至少有一个分量无法迈出这一步，剩余 29 个仅通过了必要条件。216 点实例中有 11 个分量被这个障碍封住，每个都是 14 点长。这解释了为什么必须允许删点或移动部分分量。

在本目录复算：

```sh
clang++ -std=c++20 -O3 surgery.cpp -o /tmp/section-surgery
/tmp/section-surgery 191 1500 2 0 317 < control.sections
gzip -dc sections.gz | /tmp/section-surgery 192 2 2 1 70384
/tmp/section-surgery 192 450 3 1 70405 < selected.sections
python3 verify.py
```

选中的 140 条原始行号见 selected.rows，全体截面的压缩副本为 sections.gz。随机重放使用 macOS 的 clang++ 与 libc++。最终验算不依赖 C++ 随机数实现。
