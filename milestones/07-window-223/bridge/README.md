# Toward an unconditional 244: kernel-checked refutations of the (2,2,3) windows

`upper_244_of_no_two_two_three` is conditional on no snake containing three consecutive internal vertices with local counts 2, 2, 3. Two radius-three window CNFs carry that premise (path vertices `0,1,3,7,6` and `0,1,3,7,15`, centres 1, 3, 7). Their DRAT refutations were checked by drat-trim only.

**G2, the refutation (done).** The repository now proves both CNFs unsatisfiable in Lean, with every unit-propagation step checked by the kernel and only the standard axioms:
- `w223_rep_unsat : WinCNF.unsat W223Rep.F`: 1,629 steps, 148,089 hints, 1,245 used clauses;
- `w223_dis_unsat : WinCNF.unsat W223Dis.F`: 17,101 steps, 926,950 hints, 2,172 used clauses.

Where things are:
- Lean modules: `work/spectral/stronger/WinCNF.lean`, `WinRup.lean`, `WinRupCmd.lean`, `W223Rep*.lean`, `W223Dis*.lean`, `W223.lean`.
- Clause semantics: `WinCNF` (`Lit := Int`, `clauseSat`, `unsat F := ∀ τ, (∀ c ∈ F, clauseSat τ c) → False`).
- Bitmask RUP checker with its soundness proof: `WinRup.rup_sound`.
- `WinRupCmd.rup_step` only builds proof terms and hands them to `addDecl`, so the kernel evaluates every check. A corrupted step is rejected; no `ofReduceBool` or native code is used.
- Each `*Inputs.lean` holds the clauses the proof uses, their indices in the full CNF and their kinds, with SHA-256 hashes of both in its header.
- The reproduction driver checks the 21 modules in about 200 s (`outputs/strengthened-direction-232-reproduction-manifest.json`).
- Tools in this folder:
  - `gen2.py` rebuilds the CNF with `wincert.Encoding` and trims the proof to LRAT with drat-trim `-L`;
  - `export_lean.py` writes the Lean modules;
  - `check_data.py` independently checks that the Lean clauses match the CNF file.

**Normalisation (done).** `work/spectral/stronger/CubePermutation.lean` shows that cube automorphisms map snakes to snakes and keep `pathDir` (mapped by the coordinate permutation), `localAlpha` and the (2,2,3) window. Any window with pairwise distinct directions can be normalised.

**G1 and assembly (done, 20 October 2026).**
- `W223G1Defs/Data/Sound.lean`: a kernel-decidable clause checker `check`, with the soundness lemma `sound : Hyp T S → blocksOK T → check T c → clauseSat (tau T S) c`. The tables in `W223G1Data` (generated by `gendata.py`) are untrusted hints that the kernel re-checks.
- `W223G1CheckRep/Dis.lean`: every used clause passes the checker (`decide +kernel`).
- `W223G1Snake.lean`, `W223G1Inst.lean`: a snake through `0,1,3,7,(6|15)` with counts 2,2,3 satisfies the hypotheses. This includes `localAlpha` equal to the number of free corners off the snake.
- `UpperBound244.lean`:
  - the window-shape case split, the normalisation and the G2 refutations give `W223G1.no_223`;
  - then `Snake9.upper_bound_244 : ∀ {m} (p : Snake m), m ≤ 244` and `Snake9.verified_interval_191_244`.
- Reproduction: `outputs/strengthened-244-reproduction-manifest.json`, 353 steps, success, standard axioms only. The G1 modules take about 60 s and G2 about 200 s.

**Result: 191 <= a(9) <= 244, unconditional and Lean-checked.**

## 242 and 241 unconditional (20 October 2026)

The same machinery discharges every premise of `upper_242_of_certified_windows` and `upper_241_of_certified_windows`:
- `WinG1Gen.lean`: a generic G1 layer whose counter blocks are classified by the kernel as endpoint budget, `alpha <= hi` or `alpha >= lo`, so ranges such as 4..6 work.
- `WinShape.lean`:
  - chord exclusion for direction patterns `abcab`;
  - normalisation forwards or backwards, which covers the 3-window shapes 0120/0123 and the 4-window shapes 01203/01230/01231/01234;
  - reversed patterns are read backwards.
- 12 window cases, each with its inputs, kernel-checked RUP steps (`WinRupImp.rup_imp_step`, curried hint arguments, about 40% smaller objects) and a G1 check: `W224*`, `W232*`, `W323*`, `W41c*`, `W2423A/B/C*`, `W3242A*`. The (2,2,3) refutations are reused for (3,2,2).
- The final theorems:
  - `UpperBound242.lean`: `Snake9.upper_bound_242`;
  - `UpperBound241.lean`: `Snake9.upper_bound_241` and `Snake9.verified_interval_191_241`.

The generator `u242/gen.py` checks the SHA-256 hashes of the committed certificate CNF and DRUP files and that `wincert.Encoding` reproduces each CNF up to the cycle cuts. It then trims the proofs with `drat-trim -L` (`u242/trim.sh`) and writes the modules.

Reproduction `outputs/strengthened-241-reproduction-manifest.json`: 606 steps, success, 26 minutes with `--jobs 2`. The 255 new modules take 2,741 module-seconds; the largest single refutation is (3,2,3) with distinct directions, 575 s. Every audited theorem uses only `propext`, `Classical.choice`, `Quot.sound`.

**Result: 191 <= a(9) <= 241, unconditional and Lean-checked.**

What is not re-derived in Lean: the CNF encodings themselves. As for 244, the kernel checks that the clauses actually used by each refutation hold for every snake (G1) and that they are unsatisfiable (G2), and that is all the theorem needs.

## Independent audit (20 October 2026)

A separate review of the whole chain returned **sound, with notes**:
- `Snake` is the core definition (`work/final_lean/Snake9.lean`), with no shadowing in any of the 686 modules; `verified_interval_191_241` quantifies over all `m` and is inhabited by the checked 191-edge witness. A test that builds a 299-edge `Snake` from raw fields and derives `False` from the theorem confirms it constrains arbitrary induced paths.
- The only `set_option`s in the 283 new modules are `Elab.async false` and `maxRecDepth`; no `native_decide`, `ofReduceBool`, `implemented_by`, `extern`, `unsafe`, `sorry`, `axiom`, `partial` or `opaque` anywhere; the step commands only build terms and submit them through `addDecl`, so the kernel evaluates every check.
- The clause checker's soundness rules are theorems about the snake's vertex set, `localAlpha` is the single constant used by the conditional theorems, and the shape case split is exhaustive (d3 = d0 or new; for five edges d4 ∈ {new, d0, d1}, with `abcab` excluded by a chord).
- One `def F` per refutation namespace is shared by the unsatisfiability theorem and the clause check.
- Note on provenance: the manifest `outputs/strengthened-241-reproduction-manifest.json` is a resumed run (351 of 606 steps cached by mtime, all source hashes equal to HEAD). A from-scratch run in an empty build directory is planned to remove that caveat.
