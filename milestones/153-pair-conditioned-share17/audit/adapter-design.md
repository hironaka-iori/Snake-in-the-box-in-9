## Existing APIs and choice

It accepts arbitrary count intervals, a realized canonical coordinate frame and the actual interval membership of each internal count. The existing count-symbol interfaces are Snake9.SymbolCredit97.canonical_symbol_share and reversed_symbol_share, in milestones/97-geometric-credit-integration/lean/SymbolCredit97.lean:23 and :43. These accept boundsOf syms. Reversal requires both the direction word and the count-symbol list to reverse. The graph wrappers encoded_forward_suffix_share and encoded_reversed_suffix_share occur at lines64 and84. The historical ShareWindow120 certificate is dispatched through CountConditionedCredits98.refuted120, line51, and its rule_credit_bound, line17. The similarly numbered milestone120 contains count exclusions and is not the historical share120 certificate.

The symbol route is applicable to the new tuple because every entry is below6 and therefore exact. Its imports include the older ConcreteRules95 and ReferenceRetention graph environment. The prepared source instead generalizes the already reused148 canonical adapter directly, retaining its first-occurrence coordinate proof. This avoids importing the older graph catalogue and permits arbitrary intervals without passing through clipped symbols.

## Prepared statements

The generic canonical_share_bound_with_bounds accepts:
- any actual snake, a fitting six-transition window and a forward canonical direction match;
- a list of five intervals;
- membership of each actual count at centre \(r+i+1\) in interval \(i\);
- the local RefutedShare certificate at the requested resolution and cap.

It concludes that the five-share sum is at least the cap plus one.

The generic reversed_share_bound_with_bounds uses a reversed canonical direction match. Its interval \(i\) is imposed on the original path centre \(r+(4-i)+1\), for \(0\le i<5\). It applies the forward theorem to the reversed snake at start \(m-r-6\). The identities used are:
\[
m-(m-r-6+i+1)=r+(4-i)+1,
\]
the existing coreAlpha_rev, and coreShare_window_rev. The fitting condition ensures all indices are in range.

The actual statement share17_of_core_unsat has the explicit premise
Unsat Snake9.LocalWindow.ShareWindow153.cnf.
It also requires \(r+6\le m\) and one of the following two complete cases:

| Canonical direction match | Actual counts in original path order |
| --- | --- |
| Forward word 012032 | \((4,4,4,5,3)\) |
| Reversed word 012032 | \((3,5,4,4,4)\) |

Its conclusion is
\[
17\le\sum_{i=0}^{4}\operatorname{coreShare}_{12}(p,r+i+1).
\]

The word012032 is canonically self-reversing, but its count tuple is not symmetric. Keeping the direction and count conditions paired prevents an incorrect reversal transfer. No count bound, parity condition or endpoint-location condition is silently dropped. The wrapper retains all five exact equalities even though the native core analysis identifies some unused lower-counter overflow clauses.

- bounds [(4,4),(4,4),(4,4),(5,5),(3,3)];
